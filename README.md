### E-CUP 2026  Product Matching

### О задаче

Задача состояла в том, чтобы по двум товарным карточкам определить, являются ли они дубликатами. На вход подавался файл с парами товаров, а для каждой пары нужно было вернуть оценку вероятности совпадения.

В карточках использовались название товара, категория и набор атрибутов. Качество решения оценивалось по Mean PR-AUC отдельно по товарным категориям.

При этом модель должна была работать в ограниченной вычислительной среде. Нужно было уложиться во время инференса, ограничение на размер Docker-образа и доступные ресурсы контейнера. Загружать модель из интернета во время проверки также было нельзя, поэтому все необходимые файлы хранились внутри образа.

### Первый этап: CatBoost

В качестве первой модели использовался CatBoost. Сначала был собран собственный набор признаков для каждой пары товаров. В него вошли обычные признаки похожести названий, точное совпадение названий, пересечение токенов, совпадение чисел и артикулов, а также признаки на основе атрибутов.

Затем модель была расширена: появились признаки, зависящие от категории товара и конкретных атрибутов. Часть признаков подбиралась отдельно для разных категорий товаров, то есть CatBoost получал общие признаки для всех товаров, а также специальные признаки, учитывающие особенности конкретной категории.

Этот подход оказался полезен для анализа данных, но по итоговому качеству уступил cross-encoder. Поэтому CatBoost остался в проекте как baseline.

### Второй этап: cross-encoder

После CatBoost основное внимание перешло к cross-encoder. Такая модель сравнивает две карточки непосредственно как пару текстов.

Для каждого товара собиралась строка следующего вида:

~~~text
Name: ...
Category: ...
Attributes: ...
~~~

Две такие строки подавались в модель одновременно. В качестве основы использовалась мультиязычная модель на базе XLM-RoBERTa - [mmarco-mMiniLMv2-L12-H384-v1](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1).

Модель возвращает числовой score совпадения. Эти значения используются для построения итогового рейтинга пар.

#### Обучение на human-разметке

Первые версии cross-encoder обучались на парах с human-разметкой. Обучающая и валидационная выборки разделялись так, чтобы товары из них не пересекались.

Валидация включала 73 128 пар из 20 категорий. Для оценки использовались общий average precision и macro average precision.

Это позволило увидеть, какие категории модель обрабатывает хорошо, а какие остаются сложными.

#### Добавление LLM-разметки

Следующим шагом стала разметка, полученная с помощью LLM. В обучение добавлялись только достаточно уверенные оценки:

~~~text
target >= 0.7
target <= 0.3
~~~

Из них была собрана выборка из 500 тысяч положительных и 1,5 миллиона отрицательных примеров. Пары, связанные с объектами из human validation, предварительно исключались.

Помимо этого, в обучение добавлялись hard negatives — пары, на которых предыдущая версия модели ошибалась или была недостаточно уверена.

#### Перевёрнутые пары

Во время дообучения для части данных добавлялись перевёрнутые варианты пар: `(A, B)` и `(B, A)`. Это помогло уменьшить зависимость результата от порядка товаров во входе.

#### Финальная версия

В финальной версии объединились:

- human-разметка;
- уверенные LLM-оценки;
- hard negatives;
- перевёрнутые пары;
- увеличенный вес human-разметки.

Итоговый датасет содержал около 6,5 млн пар. Обучение проходило на двух GPU Tesla T4 и заняло примерно 3 часа 54 минуты.

Основные параметры обучения:

- максимальная длина текста: 256 токенов;
- learning rate: `3e-7`;
- batch size на одной GPU: 4;
- gradient accumulation: 8;
- 16 000 шагов оптимизации.

На внутренней валидации финальная модель получила:

~~~text
Overall average precision: 0.771224
Macro average precision:   0.713127
~~~

Результат лучшей опубликованной версии:

~~~text
Mean PR-AUC: 0.43360951574694084
~~~

Предыдущие версии постепенно улучшались:
